# Testing

## Offline

ESP nélküli webes tervezéshez használd a `RadioRecorder: Web Preview (offline)` taskot vagy futtasd a `python -m scripts.preview_web --scenario ready` parancsot (`ready`, `missing-sd`, `recording` vagy `wifi-failure`). A külön HTML/CSS/JS forrásokat és a szimulált API-t a [webes fejlesztési útmutató](web-development.md) ismerteti. A standard offline tesztcsomag localhost HTTP-tesztekkel ellenőrzi ezt; nincs szüksége csatlakoztatott eszközre.

Install the PC serial dependency with `python -m pip install -r scripts/requirements-test.txt`. Tkinter is included with the Windows Python installation used for the viewer.

VS Code has two test tasks: `RadioRecorder: Offline Tests` and `RadioRecorder: Online Tests`; the web preview, radio programming, and OLED viewer utility tasks remain available. The offline suite runs unit tests and a PlatformIO build. The online suite is **write-enabled**: it runs a brief serial SD recording and deletes only its verified file, checks OLED, then checks AP-only/no-NTP RTC with a guarded software reboot. If the ESP HTTP address is reachable, it also records and deletes a verified WAV via the Wi-Fi API and serial cleanup. Tests run sequentially so only one owns COM at a time. The online runner does not switch PC Wi-Fi, flash firmware, write radio memory, or deliberately trigger a watchdog reset. Connect the PC to the ESP AP yourself for Wi-Fi coverage. If HTTP is unreachable, Wi-Fi is SKIP rather than FAIL; a reachable but broken API is FAIL. The RTC reboot check may SKIP if its safety prerequisites or required firmware are absent. Both suites print a final pass/fail/skip summary, repeat failures at the end, and save timestamped output in `.test-logs/`.

A rádió státusz/kiolvasás/írás egyedi taskjait, parancsait és megerősítéseit a [rádióprogramozási útmutató](radio-programming.md#pc--vs-code) tartalmazza; ezek nem részei egyik tesztcsomagnak sem. A CLI read-only smoke parancsai továbbra is az alapértelmezett egyedi próbák. Felvételt csak szabad COM-porttal és tudatosan indíts; a törlést ellenőrizd a naplóban.

The firmware enables a 10-second ESP-IDF Task Watchdog. It monitors both core idle tasks and the Arduino loop; recorder and speaker workers are subscribed only while active and feed it as they make progress. A non-yielding infinite loop or a stalled active worker therefore triggers panic/reboot. A watchdog reset is not itself proof that the original fault is fixed; inspect the reset log and reproduce the triggering workload.

PC-driven hardware and Wi-Fi tests print a pass/fail/skip summary and write timestamped details to `.test-logs/` in the workspace root. Git ignores this directory.

The ESP-IDF Task Watchdog uses a 10-second timeout, monitors both core idle tasks, the Arduino main loop, and active recorder/speaker work. Normal workers blocked on notifications are not subscribed. A detected stall triggers panic/reset. The standalone `python -m scripts.test_watchdog` is intentionally excluded from the online suite: it sends serial command `w`, freezes the main loop, and verifies a watchdog panic followed by firmware reboot. This test interrupts the current ESP session and should only be run when an automatic reset is acceptable.

## Serial hardware

### UV-5R konfiguráció kiolvasása

A firmware **0.1.45** verziójától a `/radio` (**Radio Programming**) oldal kézi indítással kiolvassa a Baofeng UV-5R konfigurációját. Ez klónozási munkamenet, nem folyamatos élő frekvencia/RSSI lekérdezés és nem a rádió MCU-firmware-ének mentése. **0.1.47-től külön opt-in írás és USB-s Python-kliens is van:** a [rádióprogramozási útmutató](radio-programming.md) írja le a mentési, előzetes összehasonlítási és visszaellenőrzési kapukat. A rádió normál vétele a munkamenet közben megszakadhat.

**Feltöltés és bekötés előtt** áramtalanítva válaszd le a kamerát; ellenőrizd a panel GPIO16/17 kivezetéseit és a 3,3 V-os logikai kompatibilitást. A rádió saját akkumulátorról működjön. A meglévő rádiós PTT-relé COM/NO, mikrofon/DAC és audio/ADC ág maradjon leválasztva. Kikapcsolt rádiónál csatlakoztasd a TRS dugókat:

| ESP32-S3 | UV-5R |
| --- | --- |
| GPIO17, UART1 TX | 3,5 mm sleeve, rádió RX |
| GPIO16, UART1 RX | 2,5 mm ring, rádió TX |
| Ellenőrzött közös GND | 2,5 mm sleeve, adat-GND |

Nem RS-232 és nem 5 V-os UART! A rádió adatjelét a programozási GND-hez képest műszerrel/oszcilloszkóppal ellenőrizd; szükség esetén megfelelő szintillesztővel használd. A korábban SPK tip–sleeve között mért DC önmagában nem igazolja a közös adat-GND biztonságát. A 3,5 mm sleeve földre zárása PTT-t aktiválhat; a szoftveres relétiltás nem véd hibás kábelezés vagy külső kapcsoló ellen. TRRS dugó helyett ellenőrzött TRS bekötés kell, a vezetékek színére ne hagyatkozz.

Új firmware feltöltése külön engedélyezett művelet legyen, szabad COM-porttal. Utána kapcsold be a rádiót, nyisd meg a `/radio` oldalt, jelöld be a bekötés/jelszint/PTT-leválasztás megerősítését, majd indítsd a kiolvasást. Az oldalletöltés és a `GET /api/radio` nem aktiválja az UART-ot. `POST /api/radio/read?confirm=1` indít (202); megerősítés nélkül 400, aktív olvasás vagy PTT esetén 409. Olvasás közben az OLED/webes PTT-impulzus és tartós bekapcsolás is tiltott. A főciklus lépésenként kezeli a 9600 baud, 8N1 protokollt; a 10 másodperces watchdog végig engedélyezett. Egy válaszra legfeljebb 1,2 másodpercet, a teljes műveletre 45 másodpercet vár. Hibánál vagy sikeres befejezéskor leállítja az UART-ot, a GPIO16/17 visszaáll bemenetre.

Modern kézfogásnál a 6144 bájtos főmemória és a 320 bájtos kiegészítő terület kerül RAM-ba, nyolcbájtos normalizált azonosítóval (6472 bájtos `.img`). A 0x1FCF bájt eldobásával érintett változatokon az utolsó 64 bájtot 16-os blokkokkal olvassa. Régi kézfogásra visszaesve konzervatívan csak a főmemóriát menti (6152 bájt), firmware-azonosító nélkül. Nem minden UV-5R feliratú új/klón modell kompatibilis; sikertelen azonosítás után ne próbálj más modellhez tartozó írási parancsot. Hibánál kapcsold ki/be a rádiót az újabb próbálkozás előtt.

A **0.1.46** verziótól a felület a szokásos UV-5R 0–40 menüpontjainak számozását követi. A globális értékek között VOICE, DTMFST, SC-REV, PTT-ID/PTT-LT, MDF-A/B, BCL/AUTOLK, LED-színek, riasztási mód, TDR-AB, STE/RP-STE/RPT-RL, PONMSG és ROGER is látszik. Külön A/B VFO-tábla mutatja a frekvenciát, lépésközt, teljesítményt, sávszélességet, RX/TX DCS/CTCSS-t, S-CODE-ot, shiftet/offsetet és sávot. A DTMF-rész az ANI/riasztási és 15 jelzéskódot, hang-/szünetidőt, az indítási üzeneteket is tartalmazza. A MEM-CH, DEL-CH és RESET műveletek, nem önálló tárolt értékek; csak megnevezve jelennek meg, végrehajtásuk nincs implementálva.

A csatornatábla a nem üres 0–127 memóriahelyeket mutatja: név, RX/TX frekvencia, CTCSS/DCS, sávszélesség, HIGH/LOW teljesítmény, scan, valamint a csatornaspecifikus BCL, PTT-ID és S-CODE. Ezek eltérhetnek a globális vagy VFO-értékektől. Az ismert választási kódok értelmezett szöveggel, az ismeretlenek `Nyers: ...` jelzéssel jelennek meg; a JSON megőrzi a nyers kódokat. Régi JSON-ból hiányzó mezőnél `Nem exportált` látszik, nem kitalált alapérték. A PTT-LT továbbra is nyers kód. A szervizkalibráció és a nem dokumentált firmware-változatfüggő bájtok a nyers `.img` részei, nem mindegyik kap külön felületi mezőt.

`GET /api/radio/image` csak teljes, sikeres olvasás után tölthető le; a JSON is exportálható. SD/NVS írás nincs. Reset vagy új olvasás törli az előző RAM-mentést; mentsd le a PC-re. A `.img` CHIRP-szerű memóriakép, de a konkrét rádióval/CHIRP-verzióval való importálás külön ellenőrzendő; visszaírásra ebben a körben ne használd. A korábbi 0.1.45 JSON csak néhány dekódolt mezőt tartalmazott, miközben az ugyanakkor mentett `.img` a többi menübeállítás bájtjait is megőrizte; az UART-kiolvasás terjedelme a 0.1.46-ban nem változott.

Offline: `python -m unittest test.test_radio_programming test.test_web_preview -v`. A valódi C++ állapotgépet a teszt PC-s UART-szimulátorral fordítja és futtatja, rádió vagy COM-port nélkül. Ehhez helyi `g++` vagy Windows alatt `pio pkg install -g -t platformio/toolchain-gccmingw32` kell; hiányában a protokollteszt SKIP. A teszt ellenőrzi a modern/régi azonosítást, 12 bájtos azonosító normalizálását, töredezett adatot, a bájteldobási kerülőutat, óraátfordulást, hibás fejlécet/ACK-t/méretet, hiányos és elmaradt választ, valamint a kép és alapmezők tartalmát. A localhost `/radio` felület **szimulált** adatokat mutat, a nyers letöltése szándékosan `preview-only.bin`, nem feltölthető rádiókép.

Valódi rádió, jelszint, UART-időzítés és AP ellenőrzése külön hardveres próba. A PC-s hardverteszt a szokásos PASS/FAIL/SKIP összesítést és időbélyeges `.test-logs/` naplót igényli; a meglévő read-only smoke tesztek nem indítanak rádióklónozást automatikusan. Protokollreferencia: [CHIRP UV-5R driver](https://github.com/kk7ds/chirp/blob/master/chirp/drivers/uv5r.py); csatlakozóirányok: [Miklor műszaki oldal](https://www.miklor.com/COM/UV_Technical.php) (a modul TX/RX feliratok helyett a rádió RX/TX irányát használd).

A menüdekóder regressziója: `python -m unittest test.test_radio_programming -v`. A C++-teszt globális/VFO bitmezőket, eltolást, tónusokat és DTMF-kódokat is ellenőriz; a Node.js-es formázóteszt a 0–40 menüpont lefedését, ismeretlen értékek és régi JSON kezelését vizsgálja. Ha a `docs/uv5r-readonly.img` és `docs/uv5r-settings.json` (vagy a böngészős `uv5r-settings (1).json`) felhasználói mintamentés jelen van, a teszt azt is közvetlenül a firmware dekóderével dolgozza fel, UART nélkül; e két opcionális mintafájl hiányában csak ez a kiegészítő próba SKIP.

### PTT-relé próba (csak kifejezett opt-in)

A build és az offline webteszt nem mérik a relé tényleges állását. A GPIO10 lábkiosztását és kamerától való leválasztását a panelen, a relémodul **aktív alacsony** polaritását, az ESP 3,3 V-os HIGH nyugalmi jelének biztos kikapcsoló hatását, a táp/GND bekötését és a COM–NO érintkezők nyitott alapállapotát a konkrét példányon ellenőrizd **feltöltés előtt**. A GPIO tápadáskor és a setup futása előtt bemenet: megfelelő, a modulhoz illő hardveres kikapcsolt alapállapot/előfeszítés nélkül boot közben továbbra is behúzhat a relé. Más aktív szintű vagy 5 V-os bemenetű modullal ne töltsd fel ezt a firmware-t; az alapállapot és a reset alatti állapot nem garantálható szoftverből. A rádió és a MIC/DAC maradjon leválasztva, a COM–NO érintkezőkön csak mérőműszer legyen.

A megfelelő bekötés igazolása után, külön engedéllyel töltsd fel a firmware-t. Resetkor és bekapcsoláskor ellenőrizd, hogy COM–NO nyitva marad; a firmware a setup első lépéseként HIGH szintet tölt a GPIO10 kimeneti tárolójába, mielőtt kimenetként engedélyezi a lábat. Az Arduino `digitalWrite` a `pinMode` előtt nem állítja a lábat. LOW szint kapcsolja be a relét. Ha a firmware elindulása után is behúz, mérd meg a GPIO10 és az IN feszültségét: a 3,3 V-os HIGH-t nem minden 5 V-os relémodul értelmezi kikapcsolásként. Az OLED **PTT aktiválás** csempéjén a rövid gombnyomás reteszeli a relét, a következő nyomás kikapcsolja; csempeváltás, Wi-Fi elvesztése és kijelzőalvás **nem** kapcsolja ki automatikusan. Alvó kijelzőn az első gombnyomás csak ébreszt. Rádiót csak ellenőrzött bekötés esetén csatlakoztass, mert a relé bekapcsolva maradhat. A webes **Beállítások → Hardver tesztoldal** linken (`/test`) az **1 mp tesztimpulzus** külön, önálló ESP-időzítővel lekapcsol; időzítőhibánál az impulzus nem indítható. A webes **Relé bekapcsolása** ugyanígy reteszelt, a **Relé kikapcsolása** vagy az **Azonnali kikapcsolás** művelettel állítható le. `GET /api/ptt-test` csak állapotot és `pulseMs=1000` értéket ad; `POST /api/ptt-test/on` impulzust indít, `POST /api/ptt-test/latch` tartósan bekapcsol, aktív állapot alatt egyik sem indít újra (HTTP 409), `POST /api/ptt-test/off` mindig kikapcsol. Mérés közben resetnél és áramkimaradáskor is ellenőrizd az elengedést. A nyílt AP-n a teszt API nincs hitelesítve: kizárólag megbízható, rádiótól leválasztott tesztkörnyezetben használd. A szokásos read-only eszköz- és Wi-Fi-tesztek **nem** indítanak PTT-t.

Upload the new firmware first (`pio run -e esp32-s3-devkitc-1 -t upload`). Only one program can open the COM port at a time: close the PlatformIO serial monitor before using the viewer, hardware tests, or upload. On this workstation the ESP appears as COM3; use `--port` for another port. The serial port is 115200 baud with DTR/RTS disabled.

Run `python -m scripts.test_device` for a non-recording check. It scans serial ports, waits up to about one second per port for a RadioRecorder status response, then keeps that port open. It verifies SD, ADC, recorder, and OLED readiness, enables serial ADC metering and validates RMS/peak/DC ranges, fetches the actual OLED buffer, tests right/left movement, opens settings with a short press, closes it with a long press, and restores the original home tile. Do not turn the physical encoder at the same time. The default does not write to SD. Use `--port COM8` only to select a known port directly.

Run `python -m scripts.test_device --record` only when an SD write is intended. Firmware 0.1.43 or newer is required. In addition to the checks above, it starts a short recording, requests stop, verifies a finalized WAV with non-zero audio data, then deletes that exact test-created file and confirms removal. This is destructive test data on the card; use it only with the correct device and an available SD card. The firmware accepts only a matching dated `RadioMan` recording path (or legacy `RECxxxxx.wav`) and refuses deletion while recording; arbitrary paths and other file types cannot be deleted with this command.

A PCM5102A soros próbához (firmware 0.1.59+) külön `--play-radio` opcióval add meg a microSD gyökeréhez viszonyított **abszolút, létező PCM WAV** útvonalat (a `microSD` előtag nélkül). A `--list-wav` (0.1.60+) csak sorosan olvas: legfeljebb 128 könyvtárbejegyzést vizsgál, kiírja a WAV-ok pontos útvonalát és a támogatott PCM formátumot. Az `i` soros állapotot ellenőrzi, `P<útvonal>\n` parancsot küld, megvárja az első teljes I²S TX-blokkot, majd `Z`-vel leállítja a rádió DAC lejátszását és ellenőrzi a `Playback error` mezőt. Az útvonal nem tartalmazhat `@` jelet (az a rádióprogramozási protokoll kezdete). Nincs PTT vagy SD-írás; a DAC analóg hangja és a tényleges hallhatóság külön fizikai mérést igényel. A PC-s próba PASS/FAIL/SKIP összesítést és időbélyeges `.test-logs/` naplót készít. A szokásos `python -m scripts.test_device --port COM3` továbbra sem indít DAC-lejátszást; szabad COM-port kell.

Run `python -m scripts.test_device --display-only` for the display-only test after uploading this firmware. It checks OLED readiness, captures all 11 home tiles and each of the 15 settings rows, rejects blank or visually duplicate views, opens the SD browser and exits it without starting playback, and restores the original tile without toggling settings, PTT, or writing to SD. Passing through either signal tile starts read-only measurement and stops it on exit.

Az OLED **Fájlkezelő** csempén rövid nyomással nyílik a microSD böngésző; forgatással öt soronként lapozható. Először a mappák, majd a WAV-fájlok szerepelnek; `..` és a hosszú nyomás a szülőmappába, gyökérben vissza a csempéhez vezet. Menün belül nincs alsó sáv; a főcsempéken csak a csempeszám marad, a „Hosszu: vissza” felirat eltűnt. WAV-on nyomva a **Hangszóró** az ESP-hangszórón, a **Rádió DAC** a PCM5102A-n indítja a támogatott PCM-fájlt (nem kapcsol PTT-t), a **Vissza** kilép. A lejátszás alatt a csempén rövid nyomás leállítja a hangot. A read-only kijelzőteszt nem választ ki WAV-ot; a hang hallható működését külön, tudatosan indított lejátszással ellenőrizd. Első DAC-próba: rádió nélkül, áramtalanított ESP-hez csatlakoztasd a DAC VIN/GND/BCK/LRCK/DIN pontjait a 3V3/GND/GPIO6/GPIO7/GPIO9 pontokhoz; külön ellenőrzött vonalszintű eszközzel hallgasd meg a DAC L és GND analóg kimenetét, indíts WAV-ot a Rádió DAC menüben vagy a webes Fájlkezelő Rádión gombjával, majd állítsd le. Ne kösd a DAC L kimenetét közvetlenül a rádió MIC-hez; a Mic− a kapcsolt PTT része, nem állandó GND. Fizikai hang, DAC PLL-lock, csillapítás és rádiós bekötés nem igazolható offline builddel.

A két kézi felvételi csempe több sorban írja ki az aktuális útvonalat; az automatikus rádiós és mikrofonos felvétel egyelőre nem indít semmit. A **Rádió Élő jel** és **Mikrofon Élő jel** csempére lépés elindítja a megfelelő jelmérést; rövid nyomás a számos RMS/csúcs nézet és a grafikon között vált. A kijelzett **Max RMS** az aktív mérés első 2 másodperce után látott legnagyobb RMS; a kezdeti túlvezérlésből a grafikon sem tárol mintát. Csempeváltáskor és kijelzőalváskor nullázódik, és újabb jelaktiválás után ismét kivárja a 2 másodpercet. A grafikon 120 képpont széles, másodpercenként egy nyers RMS-oszloppal, amelyeket mind a mért maximumhoz igazítva újrarajzol; a régi minták balra kifutnak. A saját mérést csempeváltáskor és kijelzőalváskor leállítja, a más alkalmazás által elindított mérést nem. Aktív soros ADC-mérés/élő hang mellett a mikrofon jelmérése nem mindig indítható. A **Wi-Fi** csempe külön STA/AP SSID-t és IP-t mutat (a hosszú STA név görgetve látható); a **Diagnosztika** buildideje `ÉÉÉÉ.HH.NN óó:pp:mm` alakú, továbbra is fordítási idő, nem a pillanatnyi NTP-óra.

A hangszóró hangerő (0–100%) és digitális erősítés (1×/2×/4×), valamint a külön rádió DAC-hangerő (0–100%, első induláskor 5%) az OLED-ről és a webről is ugyanazt az állapotot módosítja. A rádió hangerő csak a PCM5102A 16 bites PCM-mintájának digitális szorzója; 100% teljes digitális szint, ezért rádióhoz kötés előtt a kimeneti szintet külön mérni és szükség esetén csillapítani kell. A webes fájlkezelő csíkja 500 ms-onként az I²S-re sikeresen továbbított PCM-bájtokat mutatja, nem a DAC analóg jelét. NVS-be csak az utolsó változtatás után 1 másodperccel ment; a gyors csúszkamozgás nem ír minden lépésnél. Reset után a mentett értékek térnek vissza, ha legalább 1 másodpercig változatlanok voltak reset előtt. Az AT24C32 külső EEPROM nincs használatban. Offline ellenőrzés: `python -m unittest test.test_oled_viewer test.test_web_preview -v`; az NVS tartósságát fizikai reset utáni lekérdezéssel lehet ellenőrizni, ami nem része a read-only teszteknek.

### Időszinkron és kézi óra

Az új RTC-próbához (firmware 0.1.54+) szabad COM-porttal futtasd: `python -m scripts.test_device --rtc --port COM3`. A soros `q` read-only parancs frissen olvassa a DS3231 UTC-időt, és mellé írja az ESP idejét, forrásjelét és az offline feltételt. A teszt ellenőrzi, hogy az RTC legalább egy másodpercet halad, az ESP órájával legfeljebb 3 másodpercet tér el, és sem mentett STA-hitelesítés, sem NTP-s `N` forrás nincs; különben FAIL, nem tekinti igazoltnak a próbát. A `--rtc-reboot` külön opt-in mód: az előző ellenőrzés után `y` soros paranccsal szoftveresen újraindítja az ESP-t, csak AP-only/mentett STA nélkül és inaktív felvétel, lejátszás, PTT, rádióprogramozás mellett. A boot után ismét olvas RTC-t, megköveteli az `R` időforrást és a valóban eltelt időt. A teszt időbélyeges `.test-logs/` naplót és PASS/FAIL/SKIP összesítést ír. A Wi-Fi kapcsolatot nem kapcsolja át és nem indít NTP-t. A szoftveres reboot **nem kapcsolja le az RTC VCC tápját**: a CR2032-es tartaléküzem bizonyításához külön, kézzel végzett teljes USB-áramtalanítás kell, miközben az elem bekötése/biztonsága ellenőrzött. Az új firmware feltöltése külön művelet; a teszt ezt nem végzi el.

Külső Wi-Fi STA-kapcsolat után az ESP NTP-t kérdez (a RadioRecorder AP önmagában nem internet). Csak sikeres SNTP-válasz után jelenik meg az `N`/„Internetről szinkronizálva”; a Wi-Fi önmagában nem elég. A webes **Beállítások → Dátum és idő** részben dátum/idő menthető és az időzóna bármikor átállítható. Az OLED **Beállítások** listájában az Év/Hónap/Nap/Óra/Perc és Időzóna soron nyomással lépj szerkesztésbe, forgatással módosíts, újabb nyomással ments, hosszan nyomva lépj ki mentés nélkül. Budapest DST az alapérték, vagy UTC és egész órás UTC−12…UTC+14 választható. Nyári idő kezdetén a nem létező helyi óra elutasításra kerül; kézi időt egy későbbi NTP-válasz felülírhat. Az ESP32 flash NVS-ben tárolja az időzónát, a kézzel beállított vagy első NTP-s időpontot és a napváltást; folyamatos másodpercenkénti írás nincs. A DS3231 UTC-ben jár, bootkor csak az érvényes (nem OSF-jelzett) RTC-időt használja: az RTC és az NVS közül a frissebb időpontot választja. Kézi mentés és minden sikeres NTP-szinkron frissíti az RTC-t; az OLED nélkül is működik, az AT24C32 EEPROM nincs használatban. A soros `i` státusz `RTC DS3231 GPIO4/5: ready`, `time invalid` vagy `unavailable` értéket ad; a Diagnosztika csempe `RTC: OK`, `RTC: hibas ido` vagy `RTC: hianyzik` feliratot mutat. Valódi hardveren ellenőrizendő: kézi időállítás után reset/áramtalanítás, majd az idő előrehaladása Wi-Fi nélkül; eltávolított vagy nem járó RTC mellett az NVS-tartalék. Ehhez firmware-feltöltés és fizikai beavatkozás kell, nem része a read-only teszteknek. Offline teszt: `python -m unittest test.test_web_preview -v`. Valódi NTP, AP és OLED helyes dátumának igazolása csak feltöltött firmware-rel és az adott hálózaton lehetséges; a jelenlegi VPN mellett Wi-Fi AP tesztet ne indíts.

### INMP441-M mikrofon (SD-írás csak opt-in)

Az I2S0 mikrofon bekötése: BCLK=GPIO6, WS=GPIO7, SD=GPIO8, VDD=3V3 és közös GND. Az L/R láb GND-re van kötve; a firmware a 32 bites sztereó I2S-adat **bal csatornáját** menti 22 050 Hz-es, 16 bites mono PCM WAV-ként. Ellenőrizd a GPIO6–8 szabad kivezetéseit és a kamera leválasztását. A soros `i` státuszban az „I2S microphone GPIO6/7/8: initialized” csak a periféria inicializálását jelzi, a hangminőséget vagy a tényleges bekötést nem.

A webes **Mikrofon jel** gomb csak I2S-mintavételt indít; SD-t nem ír és nem indít PTT-t. A `GET /api/mic/signal` az `enabled`, `active`, `sequence`, `rms`, `peak` és `fault` mezőket adja, a `POST /api/mic/signal/on` és `/off` kapcsolja. RMS/csúcs: 100 ms-os ablakok, 16 bites PCM-egység. Mikrofonfelvétel közben ugyanaz a minta frissíti a kijelzést. Négy másodperc lekérdezés nélkül a mintavétel leáll. Az ADC grafikon/soros mérés és az ADC élő hallgatás mellett a mikrofonmérés nem indítható (HTTP 409). Offline ellenőrzés: `python -m unittest test.test_web_preview -v`; az előnézet szintértékei szimuláltak. Új firmware feltöltése és valódi mikrofonmérés csak külön engedéllyel, a rádió leválasztása és a COM port kizárólagos használata mellett; hangszintet fizikai mérés nélkül ne tekints igazoltnak.

A read-only és a display-only teszt **nem indít mikrofonfelvételt**. A mikrofon az OLED **Mikrofon** csempén rövid nyomással, vagy a webes főoldal **Mikrofonfelvétel indítása** gombjával (`POST /api/mic/start`) indul; ugyanott újabb nyomással, illetve `POST /api/stop` paranccsal állítható le. Csak az egyik forrás rögzíthet egyszerre, és mikrofonfelvétel nem indul aktív élő ADC-hallgatás közben. A lezárt WAV a szokásos felvétellistában jelenik meg. SD-írásra és a próba pontos fájlnevének törlésére **külön engedéllyel** indíts rövid felvételt, majd ellenőrizd a fejlécet, a nem nulla hangadatot és a hallható beszédet. A hálózati AP-tesztet VPN mellett hagyd ki; a localhost előnézet tesztje nem csatlakozik az ESP-hez.

## Screen timeout

The OLED shows the previous project's built-in 128x64 ClearSky splash during boot, then returns to the home screen. A short firmware-generated startup melody plays through the I2S speaker; no SD file is read. Successful recording start and stop events play separate short melodies through the same firmware-generated path.

Serial status and the OLED **Diagnosztika** tile show both firmware version/build number and the compiler's embedded `__DATE__`/`__TIME__` timestamp. The timestamp is the compilation time; upload builds increment the firmware build number through the existing upload hook.

The OLED timeout defaults to 5 minutes. The encoder settings include `Kijelzo ido`: turn to set 0–999 minutes, press to finish editing; 0 means never turn off. When asleep, the first encoder movement or button press only wakes and redraws the display; that input is consumed and does not navigate or activate a tile. The next input performs its normal action. The MCU and recorder keep running while the panel is in U8g2 power-save; this saves display power only, not the ESP32/Wi-Fi/ADC baseline.

## Wi-Fi modes

With no saved external network, boot starts the open `RadioRecorder` AP. Saved credentials trigger a 15-second station connection attempt while the AP stays available; failure falls back to AP. On successful join, `Keep AP host` (unchecked by default) selects AP+STA; otherwise the device switches to STA-only. The password is stored in ESP32 NVS and is never returned by status endpoints. The `/settings` page can scan, select an SSID, enter a password, connect, and forget the network. `GET /api/wifi/status` reports the current mode, IP, saved SSID, Keep AP Host choice and timeout without returning the password. `POST /api/wifi/scan` starts a scan and `GET /api/wifi/scan` polls results; `POST /api/wifi/connect` takes `ssid`, `password` and `keepApHost`; `POST /api/wifi/forget` clears credentials and starts the open AP. The Wi-Fi home tile shows mode/SSID/IP and its short press forgets saved credentials; Wi-Fi auto-off is also on the OLED settings list.

Wi-Fi auto-off defaults to 5 minutes; 0 disables it. Encoder and web request activity reset the timer. The radio remains enabled during recording, live audio, scans, or a connection attempt. If STA-only Wi-Fi times out, an encoder action can re-enable Wi-Fi; the normal saved-network attempt runs again with AP fallback. After forget, the AP starts immediately. The AP is open, so use only a trusted environment.

The main web page links to `/settings`; that page links back to `/`. `GET /api/settings` returns `screenOffMinutes`; `POST /api/settings?screenOffMinutes=N` validates and saves the 0–999 value. Values are stored in ESP32 NVS via `Preferences` and loaded on boot. The settings page has a **Kijelző felébresztése** button backed by `POST /api/display/wake`; saving a timeout also wakes the panel. The Wi-Fi AP is open, so only use its setting route on a trusted test network.

The two VS Code test tasks run the offline and online suites above. Individual checks use the command catalog in this document; close the serial monitor and OLED viewer before running serial tests. HTTP checks require the PC to reach the ESP's current AP or STA IP. The watchdog reset check is separate from the online suite and should be run only when an ESP reset is acceptable.

Run the `RadioRecorder: OLED Viewer` task or `python -m scripts.oled_viewer` for a live PC image; it uses the same serial port discovery. Left/Right emulates rotation, Enter a short press, and Space (or Escape) a long press; a brief Space tap sends one long-press event. "Kép mentése" saves a portable bitmap (PBM) screenshot. A short press can start or stop recording when the Felvetel tile is selected, just like the physical button.

Serial commands: `j` left, `l` right, `k` short press, `b` long press, `d` OLED frame, `p` OLED menu state, `o` force OLED sleep for wake testing, `w` deliberately stall the main loop for the watchdog reset test, `m` serial ADC meter toggle, and `x` followed by the exact `/YYYY-MM-DD/RadioManYYMMDD_HHMMSS.wav` path and newline to delete that test recording (legacy `RECxxxxx.wav` is also accepted). Existing commands remain `i` status, `r` recording start, `s` recording stop, `f` low-pass toggle. `d` returns `OLED_FRAME 128 64 ` plus 2048 uppercase hexadecimal digits and newline. The 1024 bytes use U8g2 vertical tiles: byte offset `(y // 8) * 128 + x`, bit `y % 8`. `p` returns `OLED_STATE tile setting inSettings editing screenSleeping`. The snapshot is on demand, so a client should poll `d` for animation. These commands are only available once the new firmware is uploaded.

## DAC output diagnostics

Starting with firmware 0.1.56, a failed radio DAC playback reports the I2S driver result and the written/expected byte count in the web status and serial log. For example, `ESP_ERR_TIMEOUT (0/2048)` means the ESP TX/DMA write timed out before sending that block; it does not mean the PCM5102A rejected the data. The DAC has no I2C address or readback. Test the DAC with the radio disconnected, and do not run a separate serial test while the OLED viewer owns the COM port.

Firmware 0.1.58+ prints the DAC channel readiness, playback state, target, file path and last error when the read-only serial `i` command is sent (also printed at boot). Readiness means that the ESP I2S channel initialized; it does not detect the physical DAC. During radio playback the microphone RX master must be enabled to provide the shared I2S0 clock to the DAC TX slave. Keep the radio disconnected for the first audible DAC test; neither the serial status nor an offline build verifies the PCM5102A analog output.
