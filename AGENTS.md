# RadioRecorder project instructions

- Every feature or bug fix must include a focused new or updated test that would fail without the change. Run the relevant tests and the PlatformIO build before reporting completion; state explicitly when physical hardware or the Wi-Fi AP could not be exercised.
- Keep read-only serial/HTTP smoke tests the default. Recording, SD writes, Wi-Fi disruption, flashing, and other device-changing tests require explicit opt-in; never run them while another tool owns the COM port.
- When an active USB/COM connection to the ESP is available after firmware changes, always upload the new firmware and run both complete offline and online suites, including their read/write SD recording, verification, and exact-file cleanup tests. This rule is standing opt-in for firmware upload and the standard online suite. Release any serial monitor/viewer connection cleanly before upload or testing; never contend for a COM port, interrupt an active recording, or silently kill another owner's session. If the port cannot be released safely or hardware/AP prerequisites are unavailable, report the blocked/skipped checks explicitly. Wi-Fi switching, deliberate watchdog resets, and radio EEPROM writes still require their separate documented safety confirmations; never invent a radio patch to satisfy a write test.
- The last OLED home tile must always be Settings (`Beallitasok`). Insert every new tile before it, and keep firmware navigation, PC display-test ordering, and focused regression tests consistent.
- PC-driven hardware and Wi-Fi tests must print a pass/fail/skip summary and save timestamped logs under the gitignored `.test-logs/` directory. A test-created SD recording must be removed after it is verified, using the exact filename created by that run.
- After every test run, especially a full test suite, review the available performance and diagnostic results and briefly interpret them in the final report, not just the pass/fail counts. State when performance/diagnostics are healthy; call out failures, concerning trends, or memory usage approaching a limit with a concrete recommended action. If metrics were unavailable, say so rather than claiming they were healthy.
- Follow `docs/testing.md` for offline, serial hardware, display, and Wi-Fi checks. Keep the OLED frame format and serial commands documented if they change.
- Increment `kFirmwareVersion` in `src/app_control.cpp` for firmware changes. Do not edit `firmware-build.txt` manually; the upload hook owns that counter.
- Keep the 10-second ESP-IDF task watchdog enabled: monitor both core idle tasks and feed the main loop plus active recorder/speaker tasks. Do not subscribe a worker while it is normally blocked waiting for work.
- Every new feature must add or update a concise high-level entry in `README.md` or its linked project documentation in the same change. Keep the README feature overview current; put operational steps and test details in the appropriate docs page.
